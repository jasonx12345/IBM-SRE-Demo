METHOD & SOURCE

How this report works

The source is IBM Research ITBench-Lite, a public fault-injection benchmark. This report uses 35 SRE experiments, their ground-truth YAML files, and 1,839 timestamped alert snapshots. It uses pinned revision d0916b08ba421ce5e672e9ad68aa947d938dfef0.

For each declared expected alert, the importer looks for a firing alert with the same name and namespace and a service or pod label matching the declared resource. An observed result links to the first matching original snapshot. Repeated snapshots do not count as additional expected alerts.

Observed means a matching row appeared. Not observed means none appeared in the published snapshots; it is a reason to investigate, not proof of monitor failure. Unknown means snapshots or resource labels were insufficient for a confident comparison.

This is recorded data from IBM Research test systems, not IBM customer production telemetry. It does not establish whether a page was delivered, whether an engineer noticed it, or the exact time from fault injection to detection.

Source and importer code are in the project repository. The public dataset is licensed Apache-2.0 according to its dataset card.
